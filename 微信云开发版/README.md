# 小满冰箱 · 微信云开发版

已从本机 Python 接口切换为微信云开发：小程序调用 `fridgeApi` 云函数，数据存放云数据库。运行这版小程序不需要启动本地后端。

**当前状态：云开发代码已实现；环境 ID 尚未填写，未实际部署，未完成真机/双微信账号验证，也未提交审核。**

## 页面

底部四个入口：我的冰箱、采购清单、我的家庭、个人中心。
另外有独立的微信登录、创建/加入家庭、添加食材、食材详情、操作记录、隐私说明页面，共 10 页。

## 下一步

1. 在微信开发者工具开通云开发，取得环境 ID。
2. 导入本目录（包含 `project.config.json`），按 [云开发部署说明](docs/云开发部署.md) 填写环境 ID。
3. 创建三个数据库集合，全部设为禁止客户端直接读写。
4. 部署 `cloudfunctions/fridgeApi`，选择云端安装依赖。
5. 编译后使用微信登录，再创建或加入家庭。

完整步骤：[云开发部署说明](docs/云开发部署.md)。
提审与验收：[发布与真机验收](docs/发布与真机验收.md)。

## 账号与数据

- 通过云函数的服务端微信身份识别账号；不接收客户端自报的 OpenID、用户 ID 或家庭 ID 作为权限依据。
- 用户可创建或加入一个家庭；邀请码有效期 7 天，创建者可更换、移除成员、转让管理权。
- 成员可管理食材和采购项；不同家庭隔离，所有变更通过事务提交。
- 请求包含幂等编号，网络失败后在个人中心恢复提交；同一编号不会重复入库。
- 支持注销账号、退出家庭；离开成员的操作记录匿名化，最后一位成员退出时删除整个家庭数据。
- 初版配额：每个家庭 20 位成员、300 批在库食材、100 项采购、最近 200 条操作记录。当前无图片/视频上传。
- 小程序中的临期提醒是页内状态，尚未实现微信订阅消息。

## 开发与检查

```powershell
npm ci
npm test
npm run check:release
```

`check:release` 在缺少云环境、登记主体或尚未完成人工验收时会失败。这是发布门槛，不表示代码单元测试失败。
模拟器图形测试使用明确标注的示例数据，不替代真实云环境和真机联调。

## 目录

```text
miniprogram/              微信小程序页面、配置、公共请求层
cloudfunctions/fridgeApi/ 云函数、事务业务和数据库适配器
miniprogram/config.js     AppID、云环境 ID、名称、联系信息
project.config.json      完整工程导入配置
release.json             真实发布验证清单
scripts/                 配置、部署、检查和模拟器脚本
database/                集合说明与禁止客户端直连的规则
tests/                   云业务和客户端测试
docs/                    部署、隐私与发布材料
backups/local-*/         本次改造前的小程序备份
server/ 与 web/          保留的旧本地后端和浏览器演示端
```

旧的 Python 数据库和恢复码不会自动迁移为微信账号。旧版 `启动后端.bat` 仅用于保留的本地浏览器演示，与云开发版无关。
