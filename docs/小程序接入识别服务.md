# 识别模型接入微信小程序：方案与接入说明

> **2026-10-20 更新**：仓库已重组成 `app/`（正式云开发版）、`vision/`（识别服务）、`local-demo/`（旧本地演示）、`docs/`。本文写于重组前，文中的 `miniprogram/`、`server/`、`web/` 均指 `local-demo/` 下的本地演示版；云开发版的识别接入见 [`app/docs/摄像与识别部署.md`](../app/docs/摄像与识别部署.md)。

> 角色：B（后端与识别处理）
> 日期：2026-10-20
> 结论先说：**模型不需要、也不应该塞进小程序包；它已经是独立服务 `vision/`，把它部署到 HTTPS 地址，小程序调用即可。**

---

## 1. 先澄清三个事实

1. **小程序端有两套**：正式交付版在 `app/miniprogram/`（11 页，云函数）；旧版单页演示在 `local-demo/miniprogram/`。`local-demo/web/` 只是浏览器演示端，不是最终形态。
2. **模型本来就不在网页里**：`vision/` 是一个独立 Python 包，通过 HTTP 暴露 `/health`、`/catalog`、`/recognize`；网页和小程序都只调用后端，后端再调识别服务。
3. **真机访问不到 `127.0.0.1`**：所以"接入小程序"的实质不是搬模型，而是把识别服务（以及业务后端）放到小程序能访问的 **HTTPS 域名** 上。

---

## 2. 两条路线：端侧推理 vs 服务端识别

| 维度 | 端侧 ONNX（`wx.createInferenceSession`） | 服务端识别（当前架构，推荐） |
| --- | --- | --- |
| 微信支持 | Beta，基础库 ≥ 2.30.0，**只接受 `.onnx`** | 无特殊限制 |
| 模型体积 | YOLOv8s 权重 22 MB，ONNX fp32 约 40 MB+，超出主包 2 MB，必须走下载 | 不占小程序包 |
| 推理实现 | 要自己写 letterbox 预处理、NMS、坐标还原、类别映射 | 服务端已全部实现 |
| 性能 | 手机 CPU 单帧几百毫秒到数秒，发热耗电 | GPU 上毫秒级；CPU 实测热态 0.79 秒/张 |
| 精度 | 量化后进一步下降；当前模型 0.15 阈值下召回 71.67%，假阳性 9.59/张 | 可用完整精度模型 |
| 部署 | 需 CDN + 本地缓存 + 版本管理 | 部署一个 HTTPS 服务即可 |
| 结论 | 仅适合"离线/无网"专项，不建议放进本期 | ✅ 采用 |

### 端侧路线的硬性限制（来自微信官方文档）

- `wx.createInferenceSession` 的 `model` 参数**目前只执行 `.onnx` 后缀**，且该能力标注为 **AI 推理能力 Beta**（基础库 2.30.0 起）。见 [wx.createInferenceSession](https://developers.weixin.qq.com/miniprogram/dev/api/ai/inference/wx.createInferenceSession.html)、[AI 使用指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/inference/tutorial.html)。
- 算子支持有限，需对照[算子支持列表](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/inference/supports.html)确认；`allowNPU` 仅 iOS 有效。
- 小程序代码包主包 2 MB、整包 20 MB（[分包加载](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages.html)），装不下模型，只能从 CDN 下载到 `USER_DATA_PATH` 后再推理，首启体验和缓存管理都要额外做。
- 微信没有现成的 YOLO 推理 SDK：预处理、NMS、类别映射、坐标还原都得自己写，且要在 iOS/Android 两个端上调精度。

**因此：端侧方案成本高、收益低，本期不做。**

## 3. 推荐架构

```text
微信小程序 ──HTTPS──▶ 业务后端 local-demo/server/app.py ──内网/HTTPS──▶ 识别服务 vision/
     │                        │
     └── 库存、家庭、采购等 ───┘
```

- 小程序只认一个业务域名（后端），识别、鉴权、入库都在后端完成。
- 识别服务可以和后端同机部署（当前默认，后端会自动拉起），也可以独立容器部署。
- 如果确实想让别的客户端（H5、另一个团队）复用模型，再单独暴露识别服务域名；**仍然建议经过后端**，因为密钥不能落到客户端。

这样"模型单独拿出来"的收益是：`vision/` 可以整体拷走独立成仓库/容器，与网页演示彻底解耦，小程序只依赖后端接口。

## 4. 识别服务独立部署

`vision/` 已是自包含目录：`src/` 代码、`configs/` 食材目录、`weights/` 权重、`Dockerfile`。

### 4.1 本机启动

```powershell
cd 冰箱管家可运行项目\fridge-keeper\vision
.\.venv\Scripts\python.exe -m food_recognition.server --host 127.0.0.1 --port 8770 --device auto
```

### 4.2 容器启动

```powershell
cd 冰箱管家可运行项目\fridge-keeper\vision
docker build -t fridge-vision .
docker run --rm -p 8770:8770 `
  -e FRIDGE_VISION_TOKEN=换成你自己的令牌 `
  -v fridge-vision-data:/data `
  fridge-vision
```

镜像默认 CPU 推理；有 GPU 时把 `requirements-torch-cpu.txt` 换成 `requirements-torch-cu128.txt`，并按显卡驱动方式启动。

> 说明：本机未安装 Docker，`Dockerfile` 已按 CPU + `src` 布局写好，但**镜像构建尚未实测**；首次构建时请确认 `weights/` 下有权重文件。

### 4.3 环境变量

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `FRIDGE_VISION_RUNTIME_DIR` | 运行期目录（YOLO 配置、抽帧临时文件），容器里挂可写卷 | `vision/.runtime` |
| `FRIDGE_VISION_TOKEN` | 开启 Bearer 鉴权；`/health` 与 `/` 保持开放 | 空（不鉴权） |
| `FRIDGE_VISION_MAX_BYTES` | 单请求上限 | 28 MB |
| `FRIDGE_DISABLE_LOCAL_VISION` | 后端不自动拉起本地服务 | 未设置 |
| `LOCAL_VISION_PORT` / `LOCAL_VISION_DEVICE` | 后端拉起本地服务时的端口/设备 | 8770 / auto |
| `RECOGNITION_URL` / `RECOGNITION_KEY` | 指向外部识别服务（设置后不再拉起本地服务） | 空 |

> 后端与本地服务共用 `FRIDGE_VISION_TOKEN`：`local-demo/server/app.py` 已改为优先用 `RECOGNITION_KEY`，否则用 `FRIDGE_VISION_TOKEN` 作为 `Authorization: Bearer`。

### 4.4 实测（本机 CPU，RTX 5060 机器上强制 `--device cpu`）

| 项目 | 结果 |
| --- | --- |
| 启动 + `/health` | 正常，返回模型、设备、运行目录、是否需要鉴权 |
| 首次识别 | 22.2 秒（含两个模型加载，属冷启动） |
| 第二次识别 | **0.79 秒** |
| 鉴权 | 无 token 返回 401；带 token 正常 |
| 样例结果 | 西瓜 1 个/块（置信度 0.215）、苹果 1 个（0.378）、胡萝卜 1 根（0.175） |

结论：CPU 可用但冷启动慢，演示建议 GPU，容器建议预热。

## 5. 接口契约（小程序/后端可直接按此对接）

### `GET /health`（开放）

```json
{"status":"ok","model":".../yolov8s.pt","device":"cpu","runtime":"/data","auth_required":true}
```

### `GET /`（开放）

服务名、端点列表、支持的 `kind`、是否鉴权。

### `GET /catalog`（需鉴权）

返回 105 类中式食材目录：`id / name_zh / name_en / category / default_unit / default_storage / shelf_life_days / aliases_zh / prompt ...`

### `POST /recognize`（需鉴权）

请求：

```json
{"kind":"photo","images":["<不含 data: 前缀的 base64>"]}
```

- `kind`：`photo` 或 `video`；`video` 传多帧（后端负责抽帧）。
- `receipt` 本地模型**不支持**，返回 400 并提示未接入。
- 单请求 ≤ 28 MB；照片只能 1 张，视频帧可多张。

响应：

```json
{
  "candidates": [
    {
      "name": "西瓜",
      "quantity": 1,
      "unit": "个/块",
      "location": "冷藏",
      "expiry": "",
      "confidence": 0.215391,
      "canonical_id": "watermelon",
      "category": "水果",
      "aliases_zh": ["西瓜"],
      "storage_options": ["冷藏"],
      "shelf_life_days": {"冷藏": [3, 7]},
      "countable": true
    }
  ],
  "meta": {"model": "...", "device": "cpu", "frames": 1}
}
```

错误码：`400` 参数/格式/不支持、`401` 鉴权失败、`404` 路径不存在、`500` 推理失败。

**候选只用于确认，不直接入库**——这是项目一直坚持的边界。

## 6. 小程序端怎么接

### 6.1 域名与开关

- 正式/体验版：`wx.request` 只能访问 **HTTPS + 已在小程序后台配置的 request 合法域名**。
- 开发者工具里勾选"不校验合法域名"只解决开发阶段，真机预览/体验版按后台配置走。
- 手机上的 `127.0.0.1` 是手机自己；局域网联调要把 `local-demo/miniprogram/app.js` 的 `baseUrl` 改成电脑局域网 IP，并允许后端 `HOST=0.0.0.0`。

### 6.2 照片识别示例（经后端，推荐）

```js
const BASE = 'https://你的后端域名'

function request(path, data) {
  return new Promise((resolve, reject) => {
    wx.request({
      url: BASE + path,
      method: data ? 'POST' : 'GET',
      header: {
        'content-type': 'application/json',
        Authorization: 'Bearer ' + (wx.getStorageSync('fridge-token') || ''),
      },
      data,
      timeout: 60000,
      success: (r) => {
        if (r.statusCode >= 200 && r.statusCode < 300) resolve(r.data)
        else reject(Error((r.data && r.data.error) || '请求失败'))
      },
      fail: () => reject(Error('网络异常，请检查后端地址')),
    })
  })
}

// 1) 选图并压缩，控制上传体积
async function pickPhoto() {
  const media = await wx.chooseMedia({ count: 1, mediaType: ['image'], sizeType: ['compressed'] })
  const file = media.tempFiles[0]
  const compressed = await wx.compressImage({ src: file.tempFilePath, quality: 70 })
  return compressed.tempFilePath
}

// 2) 读成 base64（去掉 data: 前缀不是必须，后端按纯 base64 处理）
function readBase64(path) {
  return new Promise((resolve, reject) => {
    wx.getFileSystemManager().readFile({
      filePath: path,
      encoding: 'base64',
      success: (r) => resolve(r.data),
      fail: () => reject(Error('读取图片失败')),
    })
  })
}

// 3) 提交识别任务 → 轮询
async function recognizePhoto() {
  const path = await pickPhoto()
  const data = await readBase64(path)
  const task = await request('/api/recognize', { kind: 'photo', data })
  for (;;) {
    const t = await request('/api/task?id=' + encodeURIComponent(task.id))
    if (t.status === 'done') return t.result
    if (t.status === 'failed') throw Error(t.error)
    await new Promise((r) => setTimeout(r, 1500))
  }
}
```

### 6.3 如果直连识别服务（只拿候选，不入库）

```js
wx.request({
  url: 'https://你的识别服务域名/recognize',
  method: 'POST',
  header: { 'content-type': 'application/json', Authorization: 'Bearer ' + token },
  data: { kind: 'photo', images: [base64] },
  timeout: 60000,
})
```

注意：直连意味着令牌下发到客户端，**只能用于内网/演示**；正式环境请让后端代理并保管令牌。

### 6.4 上传体积建议

- `wx.compressImage` 压到长边 1280、质量 70，通常 200–600 KB，base64 后 < 1 MB。
- 视频不要在小程序里转码；30 秒内、20 MB 以内，后端用 FFmpeg 抽帧。
- `wx.request` 超时最多 60 秒，识别走"提交 + 轮询"，不要同步等待。

## 8. 结论

- **模型不搬进小程序**：微信端侧推理是 Beta、只吃 ONNX、包体放不下、还要自己写预处理和 NMS，本期不划算。
- **模型已经是独立服务**：`vision/` 现在有 Dockerfile、可配置运行目录、可选 Bearer 鉴权，能整体拷走独立部署。
- **小程序接入只需要一个 HTTPS 地址**：云开发版在 `app/` 里通过云函数调用识别服务（见 `app/docs/摄像与识别部署.md`）；本地演示版则改 `local-demo/miniprogram/app.js` 的 `baseUrl` 联调。

下一步如果要继续，我建议按这个顺序：① 把识别服务部署到一台有公网 HTTPS 的机器/云托管 → ② 小程序后台配域名、真机跑通照片识别 → ③ 再决定是否需要直连模型服务。
