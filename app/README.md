## 账号与数据

- 通过云函数的服务端微信身份识别账号；不接收客户端自报的 OpenID、用户 ID 或家庭 ID 作为权限依据。
- 用户可创建或加入一个家庭；邀请码有效期 7 天，创建者可更换、移除成员、转让管理权。
- 成员可管理食材和采购项；不同家庭隔离，所有变更通过事务提交。
- 请求包含幂等编号，网络失败后在个人中心恢复提交；同一编号不会重复入库。
- 支持注销账号、退出家庭；离开成员的操作记录匿名化，最后一位成员退出时删除整个家庭数据。
- 初版配额：每个家庭 20 位成员、300 批在库食材、100 项采购、最近 200 条操作记录。
- 可选附件：图片最多 4 MB，视频最多 30 秒、12 MB；附件保留 30 天，每个家庭最多 100 个。需先完成存储规则与清理任务配置再开启。
- 可选识别（都需要独立部署的 HTTPS 服务，令牌只放云函数环境变量）：
  - 包装 OCR：`OCR_URL` + `OCR_TOKEN`，只读取包装文字，不从生产日期推算到期日。
  - 食材检测：`VISION_URL` + `VISION_TOKEN`，返回候选清单供用户核对，不会自动入库。
- 小程序中的临期提醒是页内状态，已接入一次性微信订阅提醒代码，待模板与定时器配置和真实送达验收。
- 临期标签以到期日当天 23:59:59 判定：已过期、今天到期、3 天内、7 天内、7 天以上、日期待补。
- 周报/月报（`report.summary`）：按天聚合入库/消耗/丢弃/盘点，保留 60 天；数量按单位分别统计；没有价格字段，金额返回 `null`。
- 菜谱（`recipe.list`）：8 个固定模板按在库食材匹配，排除过期批次，不是 AI 生成。
- 每日待办（`todo.list`）：临期批次 + 未完成采购；应用内查看，不推送手机通知。
- 数据导出（`account.export`）：导出当前家庭的食材、采购、操作记录与统计 JSON，不含邀请码和 OpenID。
- 家庭别名（`alias.list/set/remove`）：用户自行设置"错误名 → 标准名"，入库时自动替换并保留 `aliasOf`；无内置词典、不自动学习，每家庭上限 50 条。
- 日期估算：`source=estimate` 且日期为空时按品类参考天数补日期，写入 `estimateBasis`；用户填写的日期永远优先。

## 本机模型识别（开发调试）

云媒体未开启时，可以用“本地预览 + 本机模型直连”在开发者工具里验证识别：

1. 启动识别服务（在仓库根目录）：
   ```powershell
   cd vision
   .\.venv\Scripts\python.exe -m food_recognition.server --host 127.0.0.1 --port 8770 --device auto
   ```
2. `miniprogram/config.js` 的 `visionUrl` 默认留空；仅在专门开发调试时填写本机识别地址。
3. 开发者工具 → 详情 → 本地设置 → 勾选“不校验合法域名、TLS 版本以及 HTTPS 证书”（正式默认 `urlCheck` 为 `true`，仅在本机调试副本中暂时关闭，发布前要改回 `true`）。
4. 首页 → 添加食材 → 拍照 / 选照片 → **用本机模型识别** → 核对候选 → 带入入库表单。

真机联调：把 `visionUrl` 换成电脑局域网 IP（如 `http://192.168.1.10:8770/recognize`），服务用 `--host 0.0.0.0` 启动，并允许 Windows 防火墙放行 8770；手机与电脑需在同一 Wi-Fi。发布前清空 `visionUrl` 并把 `urlCheck` 改回 `true`。

## 开发与检查

```powershell
npm ci
npm test
npm run check:release
```

`npm test` 运行云业务、客户端、媒体、统计/菜谱/待办、本机识别、微信订阅提醒、导出、别名与日期估算测试（当前 61 项），并静态检查页面、路由和权限规则。
依赖审计结论见 [`docs/依赖审计.md`](docs/依赖审计.md)。
`check:release` 在缺少云环境、登记主体或尚未完成人工验收时会失败。这是发布门槛，不表示代码单元测试失败。
模拟器图形测试使用明确标注的示例数据，不替代真实云环境和真机联调。
