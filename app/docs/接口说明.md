# 小满冰箱云开发版 · 接口说明

> 版本 2.1.0 · 更新 2026-10-22
> 所有接口通过 `wx.cloud.callFunction({ name: 'fridgeApi' })` 调用，无自有 HTTPS 服务。

## 1. 调用约定

```js
const res = await wx.cloud.callFunction({
  name: 'fridgeApi',
  data: { action: 'item.add', data: { items: [...] }, key: '1729555200000-abc123' },
  config: { env: cloudEnv }
});
// res.result = { ok: true, data: ... } 或 { ok: false, error: { code, message } }
```

- `action` 必填，必须是下文列出的动作。
- `data` 必须是对象（不能是数组）；整个请求体上限 **24 KB**，图片/视频走云存储，不经过这里。
- **写操作必须带 `key`**；读操作不需要。
- 身份由云函数从 `getWXContext()` 读取 `OPENID/APPID` 计算，客户端传的任何用户/家庭 id 都不作为权限依据。
- 首次登录（`login`）必须携带当前隐私版本号，当前为 `2026-10-27-reminders`。

### 1.1 幂等键 `key`

- 格式：`毫秒时间戳-随机串`，例如 `1729555200000-a1b2c3`。
- 时间戳允许范围：当前时间前 24 小时 ~ 后 5 分钟；超时返回 `EXPIRED_REQUEST`。
- 同 key + 同内容：直接返回上次结果，不会重复写入。
- 同 key + 不同内容：返回 `KEY_CONFLICT`，要求用户刷新后重做。
- 回执保留 24 小时，每个账号最多 400 条；超出返回 `DAILY_LIMIT`。

### 1.2 限额

| 项目 | 限制 | 错误码 |
| --- | --- | --- |
| 请求频率 | 100 次/分钟/账号 | `RATE_LIMITED` |
| 写操作 | 400 次/24 小时/账号 | `DAILY_LIMIT` |
| 家庭成员 | 20 人 | `LIMIT` |
| 在库批次 | 300 批 | `LIMIT` |
| 采购清单 | 100 项 | `LIMIT` |
| 操作记录 | 最近 200 条 | — |
| 家庭附件 | 100 个 | `LIMIT` |
| 按日统计 | 保留 60 天 | — |
| 家庭文档 | 700 KB | `LIMIT` |

## 2. 动作总表

| action | 类型 | 参数 `data` | 返回 |
| --- | --- | --- | --- |
| `login` | 写（无需 key） | `policyVersion` | `{ user, home }` |
| `session` | 读 | — | `{ user, home }` |
| `snapshot` | 读 | — | `{ user, home, items, shopping, events, revision }` |
| `profile.update` | 写 | `name` | `{ user }` |
| `home.create` | 写 | `name` | `{ homeId }` |
| `home.join` | 写 | `invite` | `{ homeId }` |
| `home.leave` | 写 | — | `{ ok: true }` |
| `home.rotate` | 写 | — | `{ invite, expiresAt }` |
| `home.removeMember` | 写（创建者） | `memberId` | `{ ok: true }` |
| `home.transfer` | 写（创建者） | `memberId` | `{ ok: true }` |
| `item.add` | 写 | `items[]`（1–20） | `{ ids }` |
| `item.update` | 写 | `id, version, name, unit, location, expiry, source` | `{ ok: true }` |
| `item.change` | 写 | `id, version, kind, quantity` | `{ ok: true }` |
| `item.get` | 读 | `id` | `{ item, events }` |
| `shopping.add` | 写 | `name` | `{ ok: true }` |
| `shopping.set` | 写 | `id, version, done` | `{ ok: true }` |
| `shopping.remove` | 写 | `id, version` | `{ ok: true }` |
| `report.summary` | 读 | `days`（7 或 30） | 见 3.1 |
| `recipe.list` | 读 | `servings`（1–10） | 见 3.2 |
| `todo.list` | 读 | — | 见 3.3 |
| `account.delete` | 写 | — | `{ ok: true }` |
| `media.*` | 读/写 | 见第 5 节 | 当前默认关闭 |

`item.change.kind` 取 `消耗` / `丢弃` / `盘点`。消耗、丢弃填本次减少量；盘点填当前剩余量（可填 0，归零后从在库列表移除），记录的是变化量。

## 3. 新增动作（2026-10-22）

### 3.1 `report.summary` — 周报 / 月报

```json
// 请求
{ "action": "report.summary", "data": { "days": 7 } }
```

```json
// 响应 data
{
  "days": 7,
  "from": "2026-10-15",
  "to": "2026-10-22",
  "source": "stats",
  "partial": false,
  "totals": {
    "in":      { "count": 5, "units": { "个": 8, "盒": 2 } },
    "consume": { "count": 3, "units": { "个": 4 } },
    "discard": { "count": 1, "units": { "盒": 1 } },
    "adjust":  { "count": 2, "units": { "个": -2 } },
    "nearExpiryConsumed": { "count": 1, "units": { "个": 2 } }
  },
  "byDay": [
    { "date": "2026-10-22", "in": { "count": 2, "units": { "个": 3 } } }
  ],
  "amount": null,
  "amountReason": "未记录价格，无法计算金额",
  "note": "数量按单位分别统计，不跨单位换算；临期消耗指消耗时批次处于今天到期或 3 天内。"
}
```

- `units` 按单位分开统计，**不做克/袋/个的换算**。
- `adjust` 的 `units` 是盘点净变化量，可能为负数。
- `nearExpiryConsumed`：消耗发生时该批次处于「今天到期」或「3 天内」。
- `amount` 恒为 `null`：当前批次没有价格字段，不编造节约金额。
- `partial: true`：家庭启用按日统计之前的时间段不完整；旧家庭会回退到最近 200 条操作（`source: "events"`），此时 `nearExpiryConsumed` 为 `null`。
- 统计写入发生在每次入库/消耗/丢弃/盘点时，随家庭文档保存，保留 60 天。

### 3.2 `recipe.list` — 菜谱

```json
{ "action": "recipe.list", "data": { "servings": 2 } }
```

```json
{
  "servings": 2,
  "recipes": [
    {
      "id": "tomato-egg",
      "name": "番茄炒蛋",
      "minutes": 15,
      "servings": 2,
      "matched": ["番茄", "鸡蛋"],
      "missing": [],
      "score": 1,
      "steps": ["番茄洗净切块，鸡蛋打散。", "..."]
    }
  ],
  "note": "固定菜谱模板，不是 AI 生成；已排除过期批次，份量仅作参考、不自动换算用量。"
}
```

- 内置 8 个固定模板，按 `matched / needs` 计算 `score`，从高到低排序，同分按耗时升序。
- 已过期批次不参与匹配；无库存时返回全部模板但 `score` 为 0。
- 只做匹配建议，不会生成用量，也不写库存。

### 3.3 `todo.list` — 每日待办

```json
{
  "date": "2026-10-22",
  "counts": { "expired": 1, "urgent": 1, "soon": 2, "shopping": 3 },
  "expired": [],
  "urgent": [{ "id": "...", "name": "牛奶", "quantity": 2, "unit": "盒", "location": "冷藏", "expiry": "2026-10-22", "band": "urgent" }],
  "soon": [],
  "shopping": [{ "id": "...", "name": "鸡蛋" }],
  "note": "这是应用内待办，不是微信订阅消息；不会推送手机通知。"
}
```

- `expired` / `urgent` / `soon` 只包含有到期日、且 `band` 对应的在库批次，按到期日升序。
- `shopping` 只包含未完成项。
- 当前没有微信订阅消息，所有提醒都必须由用户打开小程序查看。

## 4. 错误码

| code | 含义 | 客户端处理 |
| --- | --- | --- |
| `INVALID` | 参数格式/长度/日期不合法 | 提示并允许修改 |
| `UNAUTHENTICATED` | 没有微信身份或未登录 | 回到登录页 |
| `CONSENT_REQUIRED` | 未同意当前隐私版本 | 展示隐私页 |
| `FORBIDDEN` | 非家庭成员 / 非创建者 | 刷新家庭状态 |
| `NO_HOME` | 还没有家庭 | 去创建/加入页 |
| `ALREADY_HOME` | 已在家庭中 | 刷新 |
| `INVALID_INVITE` | 邀请码无效或过期 | 让用户重新输入 |
| `NOT_FOUND` | 食材/采购项/附件不存在 | 刷新列表 |
| `CONFLICT` | 版本号过期（并发修改） | 刷新后重试 |
| `KEY_CONFLICT` | 同 key 提交了不同内容 | 刷新后重做（换新 key） |
| `EXPIRED_REQUEST` | 请求 key 过期 | 刷新后重做 |
| `RATE_LIMITED` | 超过 100 次/分钟 | 稍后重试 |
| `DAILY_LIMIT` | 超过 400 次写/天 | 次日再试 |
| `LIMIT` | 达到成员/批次/采购/附件上限 | 提示清理 |
| `TRANSFER_REQUIRED` | 创建者退出前需先转让 | 引导转让 |
| `MEDIA_SETUP` | 媒体云服务未开启 | 用本地预览/手动录入 |
| `OCR_SETUP` | 包装识别未部署 | 手动填写 |
| `VISION_SETUP` | 食材检测未部署 | 手动填写 |
| `VISION_FAILED` | 识别服务失败 | 稍后重试或手动填写 |
| `INTERNAL` | 未预期错误 | 提示重试，保持 pending 以便恢复 |

## 5. 媒体动作（当前默认关闭）

需要云函数环境变量 `MEDIA_READY=true` 且小程序 `config.js` 的 `mediaCloudEnabled=true` 才会启用；当前两者都为 false，页面只做本地预览。

| action | 说明 |
| --- | --- |
| `media.prepare` | 申请上传路径与附件 id（`kind: image|video`，`size` 校验） |
| `media.commit` | 校验 fileID/大小/文件头，复制到 `private-media` |
| `media.list` | 当前家庭的可见附件 |
| `media.url` | 60 秒临时下载链接 |
| `media.ocr` | 包装文字识别（`OCR_URL`） |
| `media.recognize` | 食材检测（`VISION_URL`），只返回候选、不入库 |
| `media.remove` | 删除附件 |

## 6. 数据结构

```text
item      { id, name, quantity, unit, location, expiry, source, version, createdAt }
shopping  { id, name, done, version, createdAt }
event     { id, itemId, name, kind, quantity, unit, actorId, actor, createdAt }
media     { id, kind, itemId, expiresAt, size }   // 对外只暴露这些字段
stats     家庭文档内部字段：{ since, days: { 'YYYY-MM-DD': { in, consume, discard, adjust, nearExpiryConsumed } } }
```

`location` 仅 `冷藏 / 冷冻 / 常温`；`source` 仅 `manual / label / estimate`；日期为 `YYYY-MM-DD` 或空字符串。

## 7. 兼容约定

- 新增动作和字段只增不改；旧客户端遇到未知错误码应回退为通用提示。
- 新动作对旧客户端不可见，不影响现有页面。
- 统计字段 `stats` 惰性创建，旧家庭无需迁移；首次写入后开始累计。

## 8. 微信一次性临期订阅

- `reminder.status`：读操作，返回 ready、templateId、pending、expiresAt、lastResult、lastAt；从不返回 OpenID。
- `reminder.subscribe`：写操作，必须带幂等 key；参数 `{templateId, accepted:true}`。只能登记当前微信和家庭，最多一条待发送；平台仍会独立验证授权。
- `reminder.cancel`：写操作，取消本人的待发送登记。
- `fridgeApi` 的定时入口不是客户端 action；伪造 Timer 事件的终端用户会被拒绝。

配置、授权限制与验收见 [微信订阅提醒部署](微信订阅提醒部署.md)。原文“没有微信订阅消息”是旧版状态，新版已有代码但未完成平台开通。
