## 公众平台模板

由管理员进入微信公众平台 → 订阅消息 → 公共模板库，按账号实际服务类目查找与物品/食品到期提醒一致的**一次性模板**。不能借用不符合业务的模板；若无合适模板，按平台流程申请。提供最终模板 ID 和完整字段列表，不提供 AppSecret。

当前适配支持：名称 `thingN`、到期日期 `dateN` 或 `timeN`，可选提示 `thingN`、批次数 `character_stringN`、剩余天数 `numberN`。实际模板字段必须逐一匹配，若有其他必填字段，先修改适配器和测试再启用，不能猜编号。文档中的编号仅为示例。

## 云函数配置

`fridgeApi/config.json` 已声明 `subscribeMessage.send` 的云调用权限，无需把 access_token 或 AppSecret 放入小程序。

部署新版 `fridgeApi`，在云函数环境变量配置：

- `REMINDER_TEMPLATE_ID`：实际模板 ID。
- `REMINDER_FIELDS`：本模板为 `{"name":"thing1","date":"time2","quantity":"character_string5","days":"number6","note":"thing3"}`。与模板 ID 一起内置，可不重复设置；切换其他模板需重新验证。
- `REMINDER_STATE`：手机体验测试用 `trial` 或 `developer`，正式发布后用 `formal`；跳转路径 `pages/today/today` 必须在对应版本中存在。
- `REMINDERS_READY`：先保持 `false`；模板、云调用权限、运行时、定时触发和隐私指引验证后设 `true`。

配置每小时一次的定时触发器，事件须含 `Type: Timer`。代码按北京时间只在 9:00–20:00 处理；不依赖控制台时区解释。云函数超时与规模应匹配，建议先用小规模测试并监测耗时。核实平台真实定时事件的微信上下文无终端用户身份，用户伪造 `Type: Timer` 不能触发群发。

当前尚未创建触发器，也未开启发送。若套餐要求收费，必须先取得费用确认。

## 一次订阅的行为

1. 用户点击提醒页按钮，直接调用 `wx.requestSubscribeMessage`，不会在页面加载时主动弹授权。
2. 微信返回该模板 `accept` 后才登记未来 7 天内的一次待发送请求，归属当前真实微信身份和当前家庭。客户端自报“同意”不会绕过微信发送端的实际授权检查。
3. 定时检查今天到期或 3 天内到期的在库食材。有临期库存时发送一条汇总提示，没有则继续等待。已过期食材不触发新通知，仍在待办页展示。
4. 每用户最多一条待发送登记，不累积多次弹窗授权；最多每天发送一条。7 天未触发则登记失效，下次定时清理。
5. 点击通知进入今日待办并重新检查账号与家庭。消息不包含具体食材名称。
6. 取消、退出家庭、移除成员或注销会取消尚未发送的登记。已经在向微信提交的消息可能无法撤回。

并发任务通过事务抢占。同一次登记的发送状态不确定时不自动重发；任务中断超过 15 分钟的发送记录在后续检查标记为结果不确定，以免重复消息。用户可查看状态并再次主动订阅。平台拒绝授权也会显示为未允许发送，不伪装成功。

## 验收

- 真机分别验证同意、拒绝、关闭订阅、取消待发送、重新订阅。
- 模板不匹配、微信报错、网络超时、定时任务中断时不重复发送。
- 两个微信账号、两个家庭；订阅者只能收到自己家庭提醒，退出/移除后不再安排消息。
- 用明确标为测试的临期食材，在白天定时窗口验证微信实际收到消息及点击跳转；测试后按用户决定处理测试数据。
- 控制台核对云函数日志与触发次数，不记录 OpenID、完整消息参数或令牌。
- 一次性订阅不是每日永久推送，不能据此宣传“打开一次以后天天通知”。

当前扫描每次最多 5000 个用户，大规模正式运营前需要持久化游标、任务分片、失败告警和费用监控；小规模演示不等于已完成规模验证。
