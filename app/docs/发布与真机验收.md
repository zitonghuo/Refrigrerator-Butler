## 隐私填报核对

代码实际处理的信息：微信提供的本小程序用户标识（服务端哈希后用作账号 ID）、自填称呼、家庭关系、食材记录、采购信息、操作记录、同意版本/时间、必要操作回执与请求计数。

不主动读取微信头像/昵称、手机号、位置、通讯录、相册、摄像头，不上传用户媒体文件。

服务提供方展示暂为冷鲜栈；正式填报的运营主体应与账号登记主体一致。部署后记录云环境地域，确认平台日志和备份的保留配置。平台隐私指引应如实填写使用的数据和目的，与小程序内说明一致，不能为通过审核勾选未使用的权限或省略实际处理的信息。

账号入口：个人中心 → 注销账号。多人家庭创建者必须先转让管理权。退出/移除成员会匿名化其历史操作；最后一位成员退出时删除整个家庭数据。可通过联系邮箱申请核实身份后的资料查询、导出、更正与删除。

隐私页面源码：`miniprogram/pages/privacy/`。上线前由账号持有人复核。

## 两个账号与真机测试

使用独立的测试云环境，不要在真实用户家庭做清库测试。审核前需要将测试微信账号加入开发者/体验成员列表，实际权限以平台为准。

| 流程 | 操作 | 通过标准 |
| --- | --- | --- |
| 登录 | A 阅读同意后进入；退出后重新进入 | 同一微信识别为原账号，不重复创建 |
| 独立家庭 | A 建立家庭甲；B 建立家庭乙 | 双方看不到对方的库存、成员、采购和记录 |
| 共享 | B 退出自己的空家庭，通过 A 邀请码加入 | 两端库存一致 |
| 临期 | 录入昨天、今天、3 天内、7 天后和未知日期 | 分档正确，未知日期不被标为安全 |
| 详情 | 修改名称、位置和日期 | 返回首页后同步更新 |
| 并发 | 两端同时对同一版本扣减库存 | 一个成功，另一个提示刷新，无负数 |
| 断网 | 提交时断网，再恢复网络和提交 | 无重复入库；个人中心能恢复原提交 |
| 采购 | A 添加，B 标记，A 刷新 | 状态一致；旧版本请求提示刷新 |
| 邀请 | 更换邀请码，再使用旧码加入 | 旧码失效；新码有效；7 天后过期 |
| 撤权 | A 移除 B，B 再查询或修改 | B 不再访问家庭；旧邀请码不能重新加入 |
| 管理权 | A 转让给 B | A 失去管理成员权限；B 可管理 |
| 注销 | 成员注销；单成员家庭注销 | 账号删除，操作匿名化；最后一个家庭被删除 |
| 直连权限 | 在测试环境客户端尝试读取/写入三个集合 | 全部被数据库规则拒绝 |
| 显示 | 小屏、长食材名、空库存、弱网、返回键 | 无遮挡、无死循环、错误可恢复 |
| 隐私 | 查看应用内及平台隐私指引 | 内容完整，联系方式有效 |

记录测试机型、微信版本、基础库版本、云环境 ID、日期和结果。设备测试不能由桌面编译检查替代。

## 发布流程

1. 完成云环境配置、数据库规则和部署。
2. 完成上表真实测试，修复发现的问题。
3. 在公众平台核实主体、服务类目、用户隐私保护指引、备案和其他当时要求。
4. 在 `release.json` 中填入真实登记主体/地域，并仅对已验证项目标记 true。
5. 运行 `npm run check:release`；通过后在开发者工具上传版本。
6. 公众平台提交审核；审核通过后由账号持有人确认发布。
7. 上线后关注云服务用量、余额、错误率和用户反馈；不要把体验环境当作永久免费资源。

公开发布并不等于无限用户容量，使用量增长后需根据实测负载调整套餐和架构。
