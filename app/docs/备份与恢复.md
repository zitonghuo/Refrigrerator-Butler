# 备份与恢复

> 更新：2026-10-27
> 适用：微信云开发环境 `cloud1-d1guygnthc98774ff`

## 1. 备份对象

| 对象 | 位置 | 方式 |
| --- | --- | --- |
| `fridge_users` | 云开发 → 数据库 | 控制台导出 JSON |
| `fridge_homes` | 云开发 → 数据库 | 控制台导出 JSON |
| `fridge_invites` | 云开发 → 数据库 | 控制台导出 JSON |
| `fridge_media` | 云开发 → 数据库 | 控制台导出 JSON（当前无附件，仍建议导出） |
| 云存储附件 | 云开发 → 存储 | 控制台导出；当前媒体关闭，通常为空 |
| 云函数代码 | 本仓库 `app/cloudfunctions/` | Git（已有） |
| 环境变量 | 云函数配置 | 手工记录 `EXPECTED_APPID`、`OCR_URL/OCR_TOKEN`、`VISION_URL/VISION_TOKEN`、`MEDIA_READY` |
| 发布清单 | `app/release.json` | Git（已有） |

> 用户级 `account.export` 导出的 JSON 只用于查阅和归档，**不能直接用于恢复**。

## 2. 备份步骤

1. 微信开发者工具 → 云开发 → 数据库
2. 依次选中四个集合 → 右上角「导出」→ 选择 JSON → 下载
3. 文件名建议：`fridge_<集合>_<YYYYMMDD-HHmm>.json`
4. 记录当前环境 ID、导出时间、导出的文档数量
5. 云存储里如果有附件，同样导出并按 `private-media/` 路径保留

建议频率：**每次发版前 + 每周一次**；重要演示前单独做一次。

## 3. 恢复步骤

按依赖顺序导入，不能颠倒：

```text
fridge_users  →  fridge_homes  →  fridge_invites  →  fridge_media
```

1. 在测试环境先演练一遍，确认导入格式和字段
2. 清空（或新建）目标集合，再导入 JSON
3. `fridge_invites` 的文档 **id 是邀请码的 SHA-256**，必须和 `fridge_homes` 里的 `invite` 字段对得上；如果只恢复了 homes 没恢复 invites，加入家庭会失败
4. 恢复后**轮换邀请码**（家庭页「更换邀请码」或 `home.rotate`），避免旧码继续可用
5. 恢复云存储文件时保持原来的 `private-media/` 路径，否则 `fileID` 对不上
6. 云函数环境变量按第 1 节重新配置，再上传部署

## 4. 恢复后验证

| 检查 | 预期 |
| --- | --- |
| 微信登录 | 能进入首页，不报 `UNAUTHENTICATED` |
| 家庭信息 | 名称、成员、创建者正确 |
| 库存 | 批次数量、临期标签、`version` 正常 |
| 采购清单 | 项目与完成状态正确 |
| 操作记录 | 最近 200 条可见，操作人正确 |
| 周报 | `report.summary` 数字与记录一致 |
| 别名 | `alias.list` 有数据（如有） |
| 加入家庭 | 用新邀请码可以加入；旧码失效 |

## 5. 注意事项

- **不要直接改控制台里的字段结构**：先导出、备份，再操作
- `fridge_users` 里的 `receipts` 是 24 小时幂等回执，恢复旧数据后可能立即过期，属正常
- `stats` 是派生数据，缺失只会让周报变 `partial`，不影响库存
- 恢复 `fridge_users` 后，用户 OpenID 哈希必须和原环境一致；**换 AppID 会导致所有账号失效**
- 附件物理文件删除失败时，`fridge_media` 记录会保留供清理任务重试
- 云开发免费额度下部分导出能力可能受限，必要时用云函数逐条读出再落盘

## 6. 检查清单

```text
[ ] 四个集合已导出，文件带日期
[ ] 环境变量已记录
[ ] 恢复顺序：users → homes → invites → media
[ ] invites 的 id 与 homes.invite 匹配
[ ] 恢复后已轮换邀请码
[ ] 登录、库存、采购、流水、周报逐项验证
[ ] 旧备份保留至少一份，未覆盖
```
